Then found and fixed the **real bug in `x11.py`'s X-NAMESPACE wiring itself**: the per-app `xauth` cookie was written `FamilyLocal` keyed to the *host's* hostname, so a client inside the container (different hostname) never matched it and silently fell back to unauthenticated → landed in `anon`, not its own namespace — isolation was **silently not happening at all** despite every prior isolated-component check passing. Fixed by rewriting the entry `FamilyWild` (xauth nlist/nmerge trick). That fix then **exposed two real xserver-side bugs in PR #3103** neither previous testing round had hit (both only reachable via the actual runtime `CreateNamespace` protocol path, not the static config file or by staying superPower): (1) a namespace created via the protocol never got a virtual root window → **NULL-deref segfault crashing the whole server** on the confined client's first `GetProperty` (i.e. any authorized management client could trivially crash the server for everyone just by using the feature) — fixed by factoring `XnsCreateVirtualRoot()` out of the boot-time-only `hookInitRootWindow()` and calling it from `XnsCreate()` too; (2) `CreateColormap` against the real root wasn't in `hookResourceAccess()`'s allowlist (unlike sibling `CreateGC`/`CreatePixmap`) → any confined GL/visual-using client got `BadAccess` and could never render — fixed by adding it. Both pushed to `draft/xns-proto` + reported as a PR comment. **Verified end to end after all fixes:** `xnamespace -s list` shows the running container's client with `refcnt=1` under `app-glxgears` (not `anon`/`root`), full GL rendering works (`glxgears` FPS output). **Next step unchanged:** praetor decision on merging #3103 — code is now proven correct by an actual full-stack run, not just isolated tests.
