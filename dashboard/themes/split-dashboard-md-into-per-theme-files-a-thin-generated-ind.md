Directive m0048 (Enterprise + praetor), 2026-07-06: this file scales poorly (see the starfleetctl row above — now a wall-of-text single cell) and concurrent per-theme edits keep colliding on the whole file. Explicitly design-only, no implementation yet. Full answers to the four posed questions live in `DASHBOARD-RESTRUCTURE.md`: (1) **Markdown + small YAML frontmatter** per theme file (slug/title/status/since/owner), mirroring Claude Code's own memory-file format — not pure YAML (prose doesn't fit cleanly) and not plain Markdown (the thin index needs a few structured fields without prose-parsing heuristics); (2) new `starfleetctl dashboard theme list|show|write|commit|new` (scoped to one file) + `dashboard reindex` (mechanically regenerates the thin index from all themes' frontmatter — this is the actual concurrency fix, since two ships touching two different theme files never collide, and two racing `reindex` runs converge to the same byte-identical output); (3) migration as **one mechanical copy-out commit**, `migrated_from: <sha>` recorded in each theme file's frontmatter since a content split can't carry per-row git history the way `git mv` would for a whole-file rename — stated as an honest limitation, not glossed over; (4) `[[slug]]` cross-refs, generalizing a convention this file *already* informally uses (the Telegram row above links `[[prefers-self-hosted-no-cloud]]`, a Claude-memory slug) — textual/grep-able, no auto-resolving link tooling. Explicitly excludes ship/agent live status (stays in `agent-bus board`, per directive). **Next:** praetor/fleet review of the proposal; implementation (once approved) should happen from an isolated `scripts/worktree` checkout, not the shared interactive one, since it's one big mechanical diff touching every row at once.

**Update 2026-07-06 (Potemkin) — implemented per directive m0073 (praetor approval via Enterprise).** Migration done from an isolated `scripts/worktree` checkout as planned. `starfleetctl dashboard theme list|show|write|new|commit` + `dashboard reindex` built and pushed (`mpbt-hq/starfleetctl@23ffbbe`) — `reindex` verified idempotent (running it twice on the same file set produces byte-identical output, the core correctness property the design relied on). All Aktive-Themen/Parkplatz rows migrated to `dashboard/themes/*.md`, `migrated_from: <sha>` recorded in each. **One real bug caught during the migration itself:** the mechanical row-splitter didn't know that a literal `|` inside a backtick code span (e.g. `` `list|show|write` `` in this very row's own original text) isn't a real table-cell boundary to GitHub's renderer — it silently truncated 3 rows' `notiz` field at the first such `|` (this row itself, "HDR display support", and "Long-term fleet architecture vision"). Caught by spot-checking file tails for sentences that stopped mid-word, not by any automated check — fixed by rejoining every cell past the 4th back into the last field instead of discarding it, re-ran clean, re-validated all files before committing. **Second collision caught mid-migration:** an early, still-buggy dry run had leaked into the shared interactive checkout (before switching to the isolated worktree) as untracked files; Constellation reasonably built on top of that stale draft for their own `long-term-fleet-architecture-vision-...md` update (`8cf8692`) — reconciled by keeping their already-committed, complete version untouched and migrating everything else fresh around it, rather than clobbering their work. `DASHBOARD.md` itself is now the thin index (~110 lines, down from ~380KB across all history); `AGENTS.md`'s dashboard-workflow description updated to match (theme files, `Read`/`Edit` as always, `reindex` after — see that file).
