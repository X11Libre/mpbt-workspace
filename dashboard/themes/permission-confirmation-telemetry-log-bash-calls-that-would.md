Directive m0050 (Enterprise + praetor), 2026-07-06. Researched the exact `PreToolUse` contract first (via the `claude-code-guide` agent): input is `{session_id, hook_event_name, tool_name, tool_input:{command}, cwd, permission_mode}`; exit 0 with empty stdout (no `hookSpecificOutput` at all) is unconditionally neutral — deny/ask rules still evaluate exactly as without the hook; real `Bash(...)` matching splits compound commands on `&&`/`||`/`;`/`|`/`|&`/`&`/newline and strips `timeout`/`time`/`nice`/`nohup`/`stdbuf`/bare-`xargs` before matching each sub-command independently (confirmed against AGENTS.md's own documented "export AGENT_ID=Foo && scripts/agent-bus board prompts" gotcha — that's exactly a sub-command-independent-match failure, not whole-line prefix matching as originally assumed there). Built `scripts/confirm-log-hook`: reimplements that matching against the union of project/local/user `permissions.allow|deny|ask`, logs one JSONL line per unmatched sub-command to `_WORK_/agent-bus/tooling-gaps/events.jsonl` (`flock`-serialized). **Two real bugs caught during live testing** (not just unit tests with crafted stdin): (1) the compound-splitter initially split `2>&1`/`>&2` FD-redirects at the bare `&`, corrupting the sub-command (`cat f 2>&1` → `cat f 2>` + `1`) — fixed by not splitting a `&` immediately preceded by `>`/`<`; (2) a hardcoded "only log when `permission_mode == default`" turned out wrong — live-wiring into the (per-host-shared, gitignored) `settings.local.json` showed a real fleet-worker session running `acceptEdits` executes an unlisted Bash command with **no visible prompt at all**, so that assumption would have silently under-collected everywhere except `default` mode. Fixed by logging every mode except `bypassPermissions` (where nothing ever prompts by definition) and recording the mode on each entry instead of filtering by it — push the "what does no-match mean in this mode" judgment call to analysis time, not collection time. **Coordinated with Pegasus per Enterprise's m0052 nudge** (their m0051 active-escalation-on-deny effort, for `dontAsk`-mode autoscaled ships, overlaps in intent): agreed on a shared `_WORK_/agent-bus/tooling-gaps/` directory + a `source: "hook"|"escalation"` field so both mechanisms feed one collection point once m0051 actually ships (currently paused per m0053, pending direct praetor sign-off since it lowers the unattended-operation confirmation bar — not this task's blocker). **Verified live, in-session, twice** (once accidentally fleet-wide via the shared `settings.local.json`, which is how bug #2 above was even caught — Constellation's own no-match commands showed up in the log without any disruption to their session; once deliberately after cutting over to the committed `settings.json`): allowed commands produce zero log entries and zero behavior change, unlisted commands (`whoami`, `pwd`, `cat …`) get logged correctly with no new prompt observed and no perceptible latency (~30ms/call measured, mostly Python startup). Added `scripts/confirm-log-report [--top N] [--words N] [--category …]` (requirement 3) — ranks the most common non-matched prefixes; empty-log-safe. **Not done, by design (requirement 4):** no new wrapper scripts or allowlist entries proposed from findings yet — needs the log to actually accumulate real fleet signal first (bare shell utilities like `cat`/`ls`/`pwd`/`echo` are unlisted and already showed up as noise in testing, but that's a "broaden the baseline allowlist" finding, not a "build a wrapper" one — a distinction worth keeping straight when this gets analyzed later). **Next:** let it run and accumulate across the fleet, periodically `scripts/confirm-log-report`, propose whatever clear pattern emerges as a new Parkplatz row (not built here).
