**2026-07-06 (Endeavour): new `tk/term` package — a VT100/xterm-family terminal emulator widget, first step toward a `lxterminal`-alike built on this toolkit (praetor request, chat).** Built in an isolated worktree (`wt/term-emulator`, based on `origin/master`, not the shared `sources/` checkout — see the earlier `tk/widget` richtext entry below for why), committed locally (`02b5b46`), **not pushed/PR'd yet** — awaiting go-ahead. Deliberately a separate data model from `widget.TextView` (see that entry): a fixed `Rows x Cols` cell grid, byte-stream-driven, no client-side insert/delete/undo. Pieces:
- **`grid.go`** — the cell buffer: primary + alternate screen, scrollback (only on a full-width top-of-screen scroll, matching real terminal semantics), scroll regions (DECSTBM), erase/insert/delete char and line operations.
- **`parser.go`** — an ECMA-48/VT100/xterm control-sequence parser on the classic Ground/Escape/CSI/OSC state machine (the same structure xterm/VTE/Alacritty's `vte` crate use). Handles cursor movement, ED/EL, SGR (colours + bold/italic/underline/etc., 8/16/256/truecolor), DECSTBM, DECSET/DECRST (alt screen, app-cursor, bracketed paste, cursor visibility, mouse-mode *flag* — not yet wired to real pointer events), DA/DSR device replies, OSC 0/1/2 title.
- **`termtype.go`** — **multiple terminal-type support was an explicit part of the ask**, done as one engine gated by a `Type`'s capability flags (`VT100`, `VT220`, `LinuxConsole`, `XTerm`, `XTerm256Color`, `XTermTrueColor`) rather than a separate parser per type: a `VT100` profile's `Colors == 0` drops all SGR colour, its `AltScreen == false` makes `?1049h` a no-op, etc. Also sets `$TERM` for the spawned shell to match. A truecolor SGR request on a lower-capability `Type` is quantized to the nearest palette colour instead of just failing.
- **`pty.go`** (Linux-only, `//go:build linux`, `golang.org/x/sys/unix`) — real `/dev/ptmx` PTY allocation (`TIOCGPTN`/`TIOCSPTLCK`), spawns the shell as session leader with the slave as controlling tty, `TIOCSWINSZ` resize. **Verified against real subprocesses**, not just parser unit tests: spawned `/bin/echo`/`/bin/cat`, checked session/controlling-tty setup and bidirectional I/O actually works.
- **`keys.go`** — keyboard event → PTY byte-sequence encoding (arrows CSI vs. SS3 by app-cursor mode, Ctrl+letter control codes, Home/End/PgUp/PgDn, bracketed-paste wrapping).
- **`term.go`** — the widget itself: `Draw()` batches same-style cell runs per row (only touches the GC's font/foreground on a real style change — same technique as `widget.TextView`'s `Highlighter` path, applied to a 2D grid instead of line spans), a `RunLoop` helper selecting on both `conn.Events()` and a PTY-reader-goroutine dirty signal (the PTY-reading goroutine only ever mutates the `Grid` under a mutex and never touches the X connection directly).
- **`demo/terminal`** — minimal standalone emulator (one window, one `Term`, spawns `$SHELL`), the toolkit-demo equivalent of `demo/editor` for `TextView`.

**70+ tests** (grid/parser/keys pure-logic + real-PTY-subprocess integration tests for `pty.go`) caught **3 real bugs before they shipped**: `Grid.PutRune` wrapped internally regardless of `AutoWrap` mode (would have made `CSI ?7l` a no-op); `SetScrollRegion` only clamped `bot` on an invalid region, leaving `top` wherever it was instead of resetting to the whole screen; and — the one worth a regression test on its own (`TestCharsetDesignationDoesNotEatFollowingText`) — the state machine mishandled `ESC ( / ) / * / +` (G0-G3 charset designation, e.g. the `\e(B` many shells/terminfo setups emit at startup) by reusing the same "waiting for ST" flag as OSC/DCS string collection, so the byte after the designator silently flipped the parser into swallow-everything-as-a-string-until-ST mode instead of returning to ground — every character typed afterward would have vanished.

**Explicitly not done yet, scoped as follow-ups (see the praetor's ask — tab manager as a *separate* program, suckless `tabbed`-style):**
1. A **generic XEmbed-based tab manager** (the `tabbed` analogue) — needs XEmbed protocol support (`_XEMBED_INFO`/`_XEMBED` client messages, reparenting) added to `go-x11proto` itself first; not started.
2. `demo/terminal`/`Term` therefore has **no tabs of its own** by design — each tab in the eventual `tabbed`-alike would be a fully independent `terminal` process reparented into a container window, so `tk/term` itself never needs to multiplex multiple `Term`s on one connection.
3. Smaller gaps noted in the commit message: mouse reporting not wired to pointer events, no Alt-sends-ESC meta encoding, no live window-title setter on `tk_core.Window` (OSC title changes are just logged by the demo for now), G0-G3 charset designation is consumed but always treated as US-ASCII (no DEC line-drawing charset).

**Also found while working on this: `demo/editor` (the `TextView` xedit-alike) exists on `debian/maint-master` but not on `origin/master`** — `wt/term-emulator` and the earlier `wt/richtext-widget` were both built off `origin/master` (per the praetor's "debian/maint-master can always be pulled up automatically" — i.e. treat `master` as the base to build on), so this isn't a blocker, just a divergence worth knowing about; not investigated further/not this session's job to reconcile.
