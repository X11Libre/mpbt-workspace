# Automated PR review (post comment + label)

Review an xserver PR and **record the outcome on the PR** — even on the maintainer's own PRs (the
bot banner makes the origin clear). The `gh` CLI is authenticated as **@metux**, so every comment
appears under the maintainer's name. Run commands from the workspace root
(`/home/nekrad/src/xorg/mpbt-workspace`).

Full reference: **`reference.md`** in this skill's directory (full detail, moved out of AGENTS.md) and **NVIDIA-ABI.md**. This skill is the
actionable checklist. Four rules apply.

## Rule 1 — Disclose it's a bot (and which ship)

Prepend this exact banner (then a blank line) to **every** comment posted under the user's name —
PR-level, summaries, and inline alike. `<ship>` is your session's `$AGENT_ID` (Star Trek ship
name; falls back to `user@host` if unset):

```markdown
> 🤖 **Automated review** — generated by Claude Code (ship: <ship>) on behalf of @metux. Not a human review.

<comment body>
```

`scripts/starfleetctl github pr comment <pr#> <body-file> --bot-review` fills in `<ship>` and prepends this for you —
prefer it over hand-copying the banner.

## Rule 2 — Assess backport-worthiness

Decide if the change is a **security vuln** or **critical bugfix** for the release lines.
- **Backport-worthy:** client-triggerable memory disclosure / OOB read-write / NULL deref /
  use-after-free, auth or access-control bypass, crashes & DoS, data corruption, regressions.
- **Not:** refactors, cleanups, style, new features, build-system churn (unless it breaks a
  release build).

If backport-worthy, **flag it and name the likely target branches** — do **not** open backports
automatically (the `/backport` skill / the maintainer does that):

```markdown
**Backport candidate** (security / critical fix): likely applies to `release/25.2`,
`release/25.1`, `release/25.0`. Applicability must be confirmed per branch — maintainer decides.
```

## Rule 3 — Check for driver-ABI breakage (NVIDIA blob can't be recompiled)

Goal is to **preserve** the binary ABI — *even old nvidia versions must keep loading*. Two things
actually matter (ignore `ABI_*_VERSION` macros — XFree86 relic, not the signal):

1. **Public data-structure layout** — any add/remove/reorder/retype of a field in a struct a
   driver sees (`ScrnInfoRec`, `ScreenRec`, `DeviceIntRec`, `InputInfoRec`, pixmap/GC/window/
   privates, …) shifts offsets → blob reads garbage.
2. **`_X_EXPORT`'ed entry points** — removing/renaming/changing the signature/semantics of any
   `_X_EXPORT` symbol the blob resolves at load.

**Verify export-removal against real blobs — don't reason "would nvidia call this?":**

```bash
scripts/fetch-nvidia-drivers              # legacy 390/470 + recent 550/570 (no install)
scripts/nvidia-abi-check Sym1 Sym2 ...    # or pipe names on stdin
```

`nvidia-abi-check` scans **both** reference paths: link-time imports (`nm -D`) **and**
runtime lookups via `dlsym`/`LoaderSymbol` (name only a string literal — invisible to `nm`). A
plain `nm` dump misses the runtime-lookup half. Call out the specific struct/symbol and the
**explicit nvidia impact**. Consult/append **NVIDIA-ABI.md**.

## Rule 4 — Label the PR with the verdict

After posting the comment, apply exactly one outcome label (REST API, **not** `gh pr edit` which
fails with the *"Projects classic deprecation"* error):

```bash
# passed (clean / only minor/advisory):
gh api --method POST repos/X11Libre/xserver/issues/<pr#>/labels -f 'labels[]=bot-review-passed'
# changes requested (real bug / regression / security or ABI break):
gh api --method POST repos/X11Libre/xserver/issues/<pr#>/labels -f 'labels[]=bot-review-changes-requested'
```

If a later revision fixes the blocking finding, swap the label to `bot-review-passed` and update
the review comment to match.

## Never auto-merge a `release/*` PR

A `bot-review-passed` verdict and green CI do **not** authorize merging a PR that targets a
release line (`release/25.2`, `release/25.1`, `release/25.0`, …). **Merges into release branches
are manual-only, by the maintainer** — fixes for existing releases must always be reviewed
independently and manually, regardless of CI status. Review, comment, and label a release PR;
then **stop**. (Auto-merge is only ever acceptable on a `master` PR, and only when the user
explicitly asks for it.) See AGENTS.md → Backport workflow (top box).
